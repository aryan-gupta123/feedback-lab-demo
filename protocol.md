# Feedback reliability: prospective protocol v2

## Question and scope
Can fixed local instruction models use a source's completed calibration record to make better fresh decisions when that source is reliable, unrelated, or systematically inverted? This is an in-context decision evaluation, not training or a real-market return claim. Trading is a synthetic numerical decision setting. This study does not claim a novel algorithm, or establish literature priority.

## Frozen mechanism
One independent path has eight completed calibration episodes and one current episode, each with two assets and cash. Latent expected net asset returns are independent Normal(0,150²) basis points. Cash is zero. All numbers are already net of costs; no additional fees are charged. Public signal = current latent expected net return + independent Normal(0,150²) error. Settled calibration returns = past latent expected net returns + independent Normal(0,100²) outcome noise. The current outcome is never shown or used for scoring.

Four paired input conditions share the same latent path, settled outcomes, public signal, and current decision:

- public_only: public signal, without the source or its calibration record.
- reliable: source forecast = latent return + Normal(0,75²) error.
- noise: independent Normal(0,150²+75²) source forecasts.
- inverted: source forecast = negative latent return + the same Normal(0,75²) error draw used for reliable forecasts.

All source conditions have equal marginal forecast variance. Reliable and inverted sources are equally informative to an observer that knows the sign; inversion tests calibration of the relationship, not a loss of information. The noise arm removes predictive information. Calibration and current observations are rounded to integer basis points. Each current forecast is generated by the same relationship as its calibration record. Eight past episodes provide 16 paired forecast/settlement examples. Calibration forecast times strictly precede settlement, and every settlement precedes the current decision. Conditional source identity, random seed, latent expected returns, and all evaluator fields are excluded from messages. Wording and schema are fixed across source arms; numeric forecasts differ. Public-only necessarily also changes the availability and length of history. Consequently, source-vs-public contrasts are effects of the whole source-plus-history package, not isolated history or attention effects.

The prompt discloses the zero-mean prior and public-error standard deviation, possible source relationships, risk-neutral objective and known control rules. It does not disclose the assigned source relationship. Each question is independent; model choices never alter later history. This is a stationary source-calibration task, not sequential agent learning or adversarial adaptation. Past settled outcomes are realistic noisy targets; no expected-return oracle is inserted into calibration.

## Baselines and estimands
Same-information baselines: cash; public signal (equivalently public-only Gaussian posterior for ranking); naive follow-current-source; fixed zero-intercept ridge regression of settled outcomes on source forecasts (16 past pairs), with ridge 150² and residual variance floored at 100², combined with the public signal. The calibrated rule is a fixed plug-in heuristic, not an optimal Bayesian posterior. All baselines use user fields only; no source-condition branch or latent values are permitted. They are frozen before development model requests and will not be tuned on development or evaluation results.

Primary outcomes per checkpoint: mean latent expected-value regret (basis points) for each source arm minus that checkpoint's own public_only regret, paired by independent path. Lower/negative is better. This measures whether the source package improves decisions relative to that model without it. Report all three contrasts together, without selecting a favorable arm. Report differences versus the calibrated statistical rule, action agreement with naive and calibrated baselines, mean regret, choice frequencies, and optimal-choice rate as descriptive secondary results. An approximately 25 bp mean regret difference is the planning scale of interest, not a post-hoc significance threshold. A reliable-vs-inverted contrast alone does not establish recognition; compare performance with public-only and same-information baselines. No verbal rationale is elicited. Results apply to direct-choice prompting, not a chain-of-thought or deliberation intervention.

Compute descriptive 95% percentile paired-path bootstrap intervals, 20,000 resamples, seed 191119. Preserve all four cells when resampling each path. Do not treat responses or the 16 calibration records as independent samples. No p-values, multiple-testing-controlled confirmatory claims, equivalence claims, checkpoint-family population claims, or model-size causal claims. Invalid responses remain in denominators; an invalid request stops a collection for review, not silent substitution. Any complete-study performance analysis requires every planned cell from the frozen eligible models.

## Development, gates and budget
- Model-independent planning simulation: 1,000 seeds 60000–60999, no model calls. Calibrated-minus-public regret had path SD about 56.4 bp (reliable), 34.0 bp (noise), and 56.9 bp (inverted), with mean improvements about 17.9/−1.5/18.6 bp respectively. This proves the test contains usable source information; it does NOT estimate LLM variance or guarantee power. For n=48 the reference normal half-width is about 16 bp in informative arms. Results remain preliminary.
- Candidates, fixed before inference: Qwen3-4B-Instruct-2507 Q4_K_M; Qwen2.5-7B-Instruct Q4_K_M; Phi-3.5-mini-instruct Q4_K_M. Exact repositories, revisions, all shard hashes and native template probes are recorded in manifests. Phi's pinned third-party GGUF is MIT per model metadata; it is a different base family, not an independent model-population sample.
- Six certain-number controls per model (three winners × reversed option order): require 6/6 correct, complete JSON. This checks menu/numeric comprehension, not source calibration ability.
- Development: four disjoint seeds 61100–61103 × four conditions = 16 requests per model. Require all outputs structurally valid; inspect decisions and confirm test/control implementation. Do not require a favorable effect or baseline victory to qualify. If controls fail, retain the checkpoint's failure and exclude it under this prospective gate; never replace it just to improve findings. If a technical prompt/interface change is necessary, version the protocol and use fresh development seeds before reopening evaluation.
- Evaluation: 48 disjoint seeds 62100–62147 × four conditions = 192 requests per eligible model, 576 if all three qualify. Exact cases are generated and manifested only by the collector at evaluation after gate review; do not inspect evaluation responses during development. Evaluation is closed until the plan is frozen with eligible models.
- Maximum initial collection: 6 controls + 16 development + 192 evaluation = 214 requests/checkpoint; 642 total if all qualify. No retries, output repair, repeated question, hidden fallback, paid inference or remote inference. Model API fees $0; host compute/storage costs are not estimated. Greedy decoding, seed 42, max 32 generated tokens, choice-only JSON (no verbal rationale), request timeout 120 seconds, CPU four threads/one slot, context 4096. Bounded cap is not permission for unlogged extra attempts.
- Four condition orders are independently permuted per path by a separate deterministic stream, shared across checkpoints. No shared conversation/cache history: fresh chat-completion messages for each case; llama.cpp may reuse identical prefix computations without changing messages.

## Integrity, review and release
Commit source/protocol before each collection. Preserve immutable source snapshots, all request starts and raw responses/failures, manifests, model/runtime identity, usage, scores and audit receipts. Auditor reconstructs inputs, verifies chronology and request/evaluator separation, independently reconstructs latent scoring values, parses raw replies and rescores. Invalid/missing cells prevent complete-study claims. Exercise the auditor on deliberately corrupted copies before final reporting. No post-evaluation prompt, gate, model or metric changes; software/report corrections must be disclosed and original raw data preserved.

Publish a readable report including null/negative results, confidence intervals, effect sizes, limitations, and failure cases. Compare current source claims against the earlier literature positioning rather than claiming novelty from a limited search. Produce one-command offline audit/analysis from a sanitized data bundle. Private source and code-containing archives must stay private; only explicitly sanitized demo/evidence may enter the public demo repository. Replaying recorded evidence is not live model inference. Add a history-ablation or shifted-reliability experiment later only under a new protocol; this study alone cannot attribute improvements specifically to calibration-history use.

## Version transition before evaluation
Version 1 made six correct Qwen3 controls and one invalid development response (choice valid, rationale 260 characters exceeding the 240-character schema bound). No evaluation calls occurred. Version 2 removes rationale generation entirely to measure the decision directly, uses new control values and disjoint development/evaluation seeds, and caps generation at 32 tokens. Preserve all seven v1 requests and report them separately from the v2 study cap. Maximum combined initial attempts across both versions: 649 (7 retained v1 + 642 v2), without retries. Models now qualify on the simpler choice-only interface; this is an openly adaptive interface change before final evaluation, not a claim that the original interface passed.

Phi's first control request returned HTTP 400 before inference: llama.cpp's automatic native-template output parser constructed a grammar with an invalid assistant-prefix token. This is an infrastructure failure, not an incorrect model answer. Retain the original manifest, start/failure pair and server log as `reliability-v2-phi35_mini-controls-parser-failed`. All candidates use the same v2 development seeds and final evaluation questions. ## Final eligibility decision, before any evaluation
Qwen3 and Qwen2.5 each passed 6/6 numeric controls and produced 16/16 valid development responses. Phi's final parser yielded valid JSON in all six controls, but only 4/6 choices were correct; both cash-winning controls failed. Per the frozen gate, exclude Phi, preserve its negative evidence and make no cross-family replication claim. Do not replace it with a more favorable model. Eligible checkpoints are qwen3_4b and qwen25_7b. Evaluation is 384 requests across 48 paired paths per checkpoint. Total combined maximum now 443 attempts, including all prior interface, adapter and failed-control attempts. Evaluation paths and source-generation/scoring/prompt remain unchanged. No effect-size or favorable-direction criterion was used in eligibility.
